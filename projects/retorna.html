Retorna.

Loyalty programs should fit the business, not force the business to fit.

Retorna is a collaborative loyalty platform designed around each company's needs. Businesses can configure how customers earn points, define rewards and redemptions, adapt policies for individual stores and run temporary campaigns. Existing sales systems connect through an API rather than being replaced.

01 / CONTEXT

The problem

Businesses want to encourage customers to return, but loyalty programs rarely work the same way everywhere. Fixed rules make it difficult to reflect each company's reward strategy, and multiple stores may need different policies or temporary campaigns.

Retorna's model is configurable by company, with store-level overrides, reward and redemption policies, and campaign rules. It connects to existing sales channels through an API so the loyalty program can fit the company's operations. Transactional integrity supports the experience behind the scenes.

02 / PRODUCT

The approach

Rather than replacing a point-of-sale system or ERP, Retorna receives sales events from those tools, applies the business's configured loyalty policies, records the points history and returns a result. Shared Django services support both the interface and the versioned API.

03 / DESIGN

Product and engineering decisions

01

Rules that match each business

Each business can define points and redemption policies, override rules for individual stores and use temporary campaigns instead of being limited to one hard-coded loyalty program.

Inspect product model
02

Integrate, don't replace

Retorna is not a point-of-sale system or ERP. Existing tools send business events through a versioned API; the loyalty platform applies its rules and records the result.

Inspect integration strategy
03

Reliable points and redemptions

Core balance-changing operations use transactional services. Idempotency and concurrency tests address repeated or simultaneous redemption requests without making those edge cases the product's purpose.
